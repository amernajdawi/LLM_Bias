Position Bias Re-measured

ARC-Challenge and OpenBookQA test sets, 200 questions each · every question asked with the correct answer in each of the four positions · 3 October 2026

Most of the strong position bias in the earlier Ollama and API runs came from the way answers were read from the model's text. With a strict reader, the same models are accurate and only mildly sensitive to answer position.

Why the earlier numbers were wrong

The earlier pipeline turned each reply into a letter in a way that invents answers. The local Ollama code took the first character A–D found anywhere in the reply, even inside a word. The cloud and OpenAI code took the first character and recorded "A" whenever it was not a letter. The prompt in config.yaml ended with "Answer:" and never asked for a single letter, and the raw replies were not stored.

Reducing the bias

Majority voting asks the four rotations and keeps the option chosen most often, as in the calibration of Pezeshkpour and Hruschka (2024). PAV, the method proposed here, also uses the four rotations. Without any answer key, it learns how strongly the model is pulled toward each position (a 4×4 table fitted with the EM algorithm of Dawid and Skene). It then weights each vote by how informative it is: an option picked from a position the model usually avoids counts more than one picked from its favourite position. PAV-adaptive asks the rotations one at a time and stops when it is 95% sure. Majority with early stop asks two random rotations and stops if they agree. Ties count as a fractional share, never as a lucky guess.

{{mit_text}} The cloud models have little bias left to remove, so the next section tests every method on a small model that does have it.

The earlier three-step mitigation (PINE-style yes/no checks, numeric labels, label rotation) is no longer used. On the earlier data its yes/no step was the weakest part, and adding it was not significantly better than numbers or rotation alone in any of the 12 comparisons. A 2026 study by Hanna and Feng also found that scoring each option in isolation does not reliably raise accuracy.

An earlier run (March 2026) used the older prompt, which ended with "Answer:" and gave no instruction. Qwen2.5-0.5B then preferred A instead of D, with a similar gap, so the direction of the pull depends on the prompt. In that run, Llama-3.2-1B answered "A" for 99% of prompts, but its four letter probabilities averaged 26%, 25%, 25% and 25%. It barely preferred any option, and after correction it was at chance level.

How the corrected runs were done

  • Models re-run with the corrected protocol: {{models}}. Three models from the earlier runs were retired by Ollama and could not be re-run: kimi-k2-thinking (16 June 2026), deepseek-v3.1:671b and glm-5 (15 July 2026). ministral-3:14b was also retired on Ollama Cloud, so the same model was re-run on a local GPU (4-bit copy).
  • Each question was asked four times in each format, rotating all four options so every option appears once in every position.
  • Prompt: the question, the options as A) … or (1) …, then "Reply with only the letter of the correct option (A, B, C, or D)." Temperature 0. Thinking was switched off where the model allows it; gpt-oss ran with low reasoning effort.
  • Answer reading accepts only a standalone label, "Answer: X", "option X", or the full text of one option. Anything else is marked invalid and asked once more with Ollama's structured output limited to the four labels. The cloud service did not always enforce that format, and replies that stay unreadable remain invalid. Invalid answers are never counted as "A".
  • Every raw reply is stored next to the parsed answer.
  • Open-weight models ({{hf_models}}) ran locally with Hugging Face transformers (the model's chat template). Their four label probabilities are stored for every prompt, so every method above is computed from the same 1,600 model calls per label format.
  • Statistics use exact McNemar tests for paired comparisons of single prompts and 95% bootstrap intervals over questions (5,000 resamples). The Qwen method comparison uses a two-sided sign-flip test over questions with Holm correction.
